## The problem

Talnio is an employee management platform. It has to work on web and on mobile, with the same data in step on both, and cover attendance, analytics, meetings and day-to-day productivity.

## What I built

I built and shipped Talnio as App Developer Intern at Social Agent (Bricstal Pvt. Ltd.), Bengaluru, from May 2025 to March 2026. The web app uses React 19 and Tailwind CSS, the mobile app uses Flutter and Dart, and both sit on Firebase Authentication and Cloud Firestore real-time sync.

- **Attendance** based on geolocation and NFC, with automated PDF and Excel reports that power workforce analytics.
- **Live video and audio meetings** through the Agora SDK.
- **AI automation:** Google Generative AI APIs automate productivity workflows.

## Key decisions

<Decisions>
  <Decision
    title="Firestore real-time sync as the shared backbone"
    why="Both clients subscribe to the same data, so a change on one shows up on the other without polling or a manual refresh."
    tradeoff="Live listeners keep reading as data changes, so queries need to be scoped tightly to stay efficient."
  />
  <Decision
    title="A Flutter app and a React web app"
    why="Mobile and web have different strengths: device features such as location and NFC on one, wide dashboards and reports on the other."
    tradeoff="Two codebases to keep consistent, so shared behaviour has to live in the data model rather than in shared UI code."
  />
  <Decision
    title="SDKs and APIs for meetings and AI"
    why="Video and audio calls and language models are specialised problems. Agora and Google Generative AI let the product add them as integrations."
    tradeoff="Each adds an external dependency and its own failure modes."
  />
</Decisions>
